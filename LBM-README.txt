Deskflow LittleBigMouse 兼容版：多屏边缘修复 + 文件中继窗口

适用：macOS 服务端连接实体键鼠，Windows 客户端运行 LittleBigMouse。
基于 Deskflow 52f92f784c8ef00fc7865a4797a2c48afdadedd0。

功能
- Windows 客户端使用本地鼠标定位并回传真实坐标，保留 LittleBigMouse 校正。
- 按每块 Windows 物理屏幕的外露边缘判断切换；不同高度的双屏都可以向下返回 Mac。
  两块 Windows 屏幕之间的接缝不会触发跨电脑切换。
- 从 Mac 进入 Windows 时，按比例算出的进入点落到该位置对应屏幕的外露边缘
  （较矮屏幕下方的空白区域会移到该屏底边），跨屏跳转不会被 LittleBigMouse 误判为穿过接缝。
- 每次移动的方向只回报一次；触屏、Windows 本机鼠标或程序移动光标到边缘不会误切回 Mac。
- 流畅度：Mac 触控板的小数位移会累积，慢速移动不再卡顿；Mac 剪贴板未变化时离开 Mac 不再重新读取转换
  （复制截图后切屏不再卡一下）；Windows 端进入期间只关闭一次鼠标加速、离开时恢复，
  不再每次移动都改系统设置；客户端每批消息只回一次应答。
- 两端鼠标速度分别调节，主菜单支持简体中文和 English。
- 文件传输改为独立中继窗口，复用现有 Deskflow 加密连接。
  原先的跨电脑原生文件拖拽接管已替换，无需按住鼠标跨过屏幕边缘。

文件中继使用
1. 两端都启动此新版并连接。Windows 请普通启动程序，使用桌面模式。
2. 两端点击“文件 → 文件中继…”（快捷键 Ctrl+Shift+F，Mac 为 Command+Shift+F）。
   打开中继时会启用相关功能；Windows 如需从服务模式切换，会重新连接。
3. 发送端把普通文件拖入窗口，或点击“选择文件”，选择对端，点击“发送”。
4. 接收端窗口会显示请求，点击“接收”后开始传输，也可以“拒收”。
5. 默认保存到“下载/Deskflow/Transfer-随机字符/”，每次使用独立目录，不覆盖已有同名文件。
   可在窗口中选择接收目录。校验与保存均成功后，发送端才显示成功。
6. 接收后可双击文件打开、打开接收目录，或将列表中的文件拖到本机文件夹。
7. 源文件保留；接收完成的文件在 Deskflow 退出或断线后仍保留。
8. 传输时可点击“取消传输”；对端未接收或长时间没有响应时会超时。

范围
- 支持中文文件名、空文件、多文件、分块传输和 SHA-256 校验。
- 一次最多 1024 个普通文件；一批文件名需唯一且符合 Windows/macOS 命名规则。
- 暂不支持文件夹和符号链接；需要时可先在本机打包为 ZIP。
- 每个中继窗口同一时间处理一批传输。
- 两端必须升级到支持文件中继的新版本，旧版不会出现在可发送对端列表中。
- 双机真实操作需要在安装后验收；自动化测试不能代替实际 Finder/资源管理器操作。

Mac 构建
安装 Homebrew 和 Xcode Command Line Tools 后，执行 bash ./build-macos.command。
脚本构建应用、core 和 7 组相关测试，打包 Qt 依赖并执行本地 ad-hoc 签名，生成 DMG。
配置包含 Homebrew 拆分 Qt 模块与 QtSvg 部署路径。
安装前退出原 Deskflow，再将新应用替换到“应用程序”。保留原配置、布局和证书。
如 macOS 提示权限，请为新应用启用辅助功能和所需的输入监控权限。

验收
- Windows 左侧 1920x1080、右侧 2000x3200 时，分别从两屏底边下移回到 Mac。
- 从 Mac 顶边左半、右半分别上移：左半进入 1K 屏底边，右半进入 3K 屏底边对应位置，不跳到 3K 屏左边界。
- Mac → Windows 和 Windows → Mac 各通过中继发送一个小文本文件。
- 再测试中文名、空文件、多文件、大于 64 KiB 的文件、拒收及传输中取消。
- 确认接收内容完整、源文件仍在、重名传输进入不同目录。


设备绑定与自动寻址（Mac / Windows）
- 首次按原来的方式连接服务器并确认其 TLS 指纹；连接成功后自动保存服务器证书身份。
- 若升级时仅有一个受信任服务器，会直接沿用该身份，无需再次输入失效的旧 IP。
- 之后在同一 IPv4 局域网中，每 5 秒通过 UDP 24801 寻找该设备的新地址；仍使用 TLS 校验被绑定的证书。
- 配置客户端窗口中可关闭自动发现，或选择“解除服务器绑定”后保存。解除绑定同时清空地址，再手动连接另一台服务器。
- 服务器和客户端都需要此版本，GUI 需保持运行（可收起到托盘）。广播被屏蔽时可通过已配对客户端的单播提示回找服务器；网络完全隔离时保留手动地址方式。
- 网络设备/系统防火墙需允许服务端 UDP 24801、客户端 UDP 24802，原来的鼠标键盘通道继续使用服务器 TCP 端口（默认 24800）。
- 证书被更换后需要重新确认并绑定；仅 IP 改变不需要重新确认身份。

- 校园网屏蔽广播时，服务器还会向最近经 TLS 认证的客户端地址单播通知。客户端固定监听 UDP 24802，收到提示后发起带随机挑战的查询，再由 TLS 身份校验确认连接。
- 服务端必须允许 Deskflow 接收本地 UDP 24801，客户端允许 UDP 24802。只有双方同时改了地址、并且广播也不可用时，才需要重新手动提供一个可达地址。


右键“发送到”（Mac / Windows）
- 无需再打开文件中继窗口并拖拽文件：在文件上点右键，选择“发送到已连接的电脑”，文件会自动发给当前已连接的对端。
- Windows：首次启动本版本后，会在资源管理器右键菜单的“发送到”中添加“Deskflow - 发送到已连接的电脑”（Windows 11 需先点“显示更多选项”）。
  文件菜单中的“添加到右键‘发送到’菜单”可随时关闭或重新开启；移动程序位置后重新启动一次即可自动修正。
  本质是 %APPDATA%\Microsoft\Windows\SendTo 中的快捷方式，等同于运行 deskflow.exe <文件…>，也可在命令行直接使用。
- macOS：在访达中选中文件，右键 → 快速操作（或“服务”）→“发送到已连接的电脑 (Deskflow)”。
  首次安装后若没有出现，请先打开一次 Deskflow，再到“系统设置 → 键盘 → 键盘快捷键 → 服务 → 文件和文件夹”勾选该项。
- 对端只有一台时自动选中并开始发送；已连接多台时会打开中继窗口让你选择；30 秒内没有连接则提示。
- 如果 Deskflow 尚未运行，会先启动并连接，再自动发送；接收端仍需点击“接收”。
- 目前同样只支持普通文件（不含文件夹）；先在本机打包为 ZIP 即可。
- 两端都需要此版本（右键菜单只在发送端使用，接收端沿用文件中继窗口）。
